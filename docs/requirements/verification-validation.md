## Верификация (корректность записи)

Закрыто в рамках **REQ §5** (2026-05-03): построчная сверка MVP-объёма FR **CRITICAL+HIGH** из [[prioritization]] и пересечения с [[NFR]].

- [x] У каждого FR/NFR есть уникальный ID и проверяемая формулировка (метрика, порог или однозначное поведение).
- [x] Нет дублирования канона без перекрёстных ссылок (безопасность: NFR-SEC + SEC-* в [[NFR]]).
- [x] Трассировка BC → FR заполнена в [[traceability]]; расхождения с [[BRD]] устранены.
- [x] Внешние ссылки актуальны или помечены временными (снимок документации: **architecture** **`docs/`** + политика **`dual_so_t`** [[../SYNC|SYNC]], тексты задач — только Issues).

## Валидация (то ли строим)

Закрыто **документально** в **REQ §5** (без полевых интервью на этом шаге): гипотезы BC, воронки и региона приняты до первого dev-спринта.

- [x] BC-001…003 и метрики воронки согласованы с продуктовой стратегией и [[BRD]] (MET-PROD/MET-TECH: горизонт MVP ~4 мес., Free→Pro, один платный тариф Pro).
- [x] Роли и лимиты тарифов (**anonymous / free / pro**) отражают гипотезу ценности для СНГ; дифференциация Free/Pro и границы воронки задаются **подпиской, привязкой фич к тарифам** и политикой продукта (см. [[SRS]] §2.2 и [[../meta/stakeholders]]).
- [x] MVP-срез по [[prioritization]] реалистичен по срокам; блок Future в [[SRS]] §4 явно отделён от обязательств MVP.

### Зрелость и версионирование спецификации (vault)

- **BRD / SRS / NFR:** согласованы с MVP-объёмом пакета 2026-05-03 и [[prioritization]]. **DR-REC:** канон сейчас — текст [[SRS]] §6; домен-модель, графические схемы БД и остальной UML вводятся **позднее** под `architecture/` и фиксируются в [[traceability]] при появлении. Артефакты старых версий репозитория **architecture** не используются.
- **[[FRS]]:** каркас (принципы + ключевые экраны); полное экранное покрытие MVP без жёсткого дедлайна до UI-спринта — см. границу во вступлении FRS.
- **График версий пакета:** репозиторий (исторический) **0.5** → первый перенос в vault **1.0** → текущая линия **2.0** (в т. ч. презентационная доска [[../summary/COOKie-v2.0.excalidraw]]). До конца MVP при **принятом CR** — только **минор** (**2.1**, **2.2**, …); **3.x** — после отдельного решения. Канон: [[../SYNC|SYNC]]; учёт в [CR / журнал](../changes/README.md).

### Сверка пирамиды (лёгкий FRS)

- **BC-001…003:** в [[BRD]] и отражены в [[SRS]] (ссылка на BRD); **[[prioritization]]** (Phase 2–3 для FR-AI / FR-MP / FR-OR) согласована с Future в [[SRS]] §4 — без признаков «Future = обязательный MVP».
- **SRS ↔ NFR:** перекрёстные отсылки сохраняются без лишнего дублирования канона.
- **[[../meta/glossary|glossary]]:** выборочная сверка терминов MVP, КБЖУ, Pro / тарифы — с [[SRS]] и UC-именами; расхождений, блокирующих §4, не выявлено.

### UML и визуализация при §4

- **Варианты использования:** канон — [[../architecture/functional/use-cases]], доска — [[../summary/COOKie-v2.0.excalidraw]]; в рамках закрытия §4 **тексты SRS/FRS не менялись**, повторная генерация диаграмм не требовалась.
- **Activity / DFD:** отложены (как в REQ §3); **информационная модель (шаг D):** см. заглушку [[../architecture/information/domain-model|domain-model]] — наполнение после появления полного набора методологических артефактов.

### Допущения и хвосты

- **OQ-001…003** из REQ §3 остаются открытыми до продуктовых решений / спринта.
- Связи **требование ↔ GitHub issue ↔ тест** — этап **§6** ([[traceability]], [[../SYNC|SYNC]]) после sprint planning.
