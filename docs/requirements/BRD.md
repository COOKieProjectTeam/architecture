# BRD — бизнес-требования

_Продуктовые цели и метрики (**ведущий слой для продукта / метрик KPI**); поведение и функции системы: [[SRS|SRS]]. Карта аудитории: [[verification-validation#REQ §4 — документирование|verification-validation (REQ §4)]]._

## Цели и проблемы бизнеса

### Бизнес-цели

**BC-001**: В горизонте **первых 4 месяцев (MVP)** — привлечь до **~1000 пользователей** и вывести функциональный MVP в оговоренный срок.

**BC-002**: Платный тариф — **Pro** (единственный платный). Целевая конверсия **Free → Pro: 8–10%** на согласованном с продуктом горизонте измерения.

**BC-003**: Поддержать интеграции с **минимум 2 крупными ритейлерами** и **минимум 2 крупными сервисами доставки еды** к согласованному сроку (детали партнёров — в SRS).

## Объём и ограничения

Спецификация покрывает:

- Функциональные требования к **MVP (четырёхмесячный горизонт)** и последующие фазы roadmap
- Нефункциональные требования (производительность, масштабируемость, безопасность)
- Требования к интеграциям с внешними системами
- Требования к аналитике и метрикам

Регион: СНГ (РФ, Беларусь, Казахстан). Итерация: MVP + Future Roadmap.

## Метрики и аналитика (продукт)

См. также расчёт метрик в [[SRS|SRS]] (FR-AN-002).

### Продуктовые метрики (MET-PROD)

**MET-PROD-001**: North Star Metric — **WAU (Weekly Active Users)** — основная метрика успеха продукта.

**MET-PROD-002**: Воронка конверсии:

- Незарегистрированный → Регистрация: цель **30%**
- Free → Pro: цель **8–10%**

**MET-PROD-003**: Engagement метрики:

- Среднее количество просмотров рецептов на пользователя в неделю: цель 10+
- Процент пользователей с минимум 1 избранным рецептом: цель 40%
- Retention D7: цель 30%, Retention D30: цель 20%

### Технические метрики (MET-TECH)

**MET-TECH-001**: SLI (Service Level Indicators): Availability 99.9%; Latency P95 < 500ms; Error rate < 0.1%.

**MET-TECH-002**: Инфраструктура: CPU < 70%; Memory < 80%; Disk < 75%.

**MET-TECH-003**: БД: PostgreSQL query P95 < 100ms; connection pool < 80%; Redis hit rate > 90%.
